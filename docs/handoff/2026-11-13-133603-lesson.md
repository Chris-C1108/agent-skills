# Session Lessons & Anti-Patterns: 确定性 YAML 解析降级陷阱与知识蒸馏血缘断裂

- Date & Time: 2026-11-13 13:36:03
- Focus Module: `skills/ddd-modeling-suite` (`scripts/dmml_linter.py`, `scripts/compile_events.py`, `probes/`)

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
- 现象表现 1：V1 `dmml_linter.py` 在目标环境未安装 `PyYAML` 时静默降级为返回 `{"raw": content}`，导致整套状态机与引用校验形同虚设；且状态机可达性检测使用 `s not in visited_to and s not in visited_from`，无法识别与初始状态断开的孤立闭环（如 `A <-> B`）。
- 现象表现 2：V1 `compile_events.py` 对输出字符串直接采用 `f'"{val}"'` 拼接而不转义双引号，且 `parse_markdown_facts` 的 `has_substance` 判定未覆盖 `read_models` 专用字段，导致 `## [READ-001]` 块被静默丢弃；同时上游 `01-raw-facts.md` 缺乏字段契约，使正则匹配极易丢失整段事实。
- 现象表现 3：在当前运行环境中直接执行 `npm run lint` 返回 `ESLint output (JSON parse failed)` 失败退出，而直接运行 `node scripts/lint-skills.js` 正常通过。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
- 依赖假设失效：静态校验脚本把第三方库（`PyYAML`）作为隐含前提，缺乏零依赖子集解析器；图论校验用局部入度/出度集合替代从 `initial_state` 出发的 BFS 遍历。
- 前后端契约断裂：Prompt 阶段产出的 Markdown 块格式、读取模型（`READ-*`）字段与脚本解析器的判空条件未对齐；字符串序列化未复用 `json.dumps` 处理引号与特殊字符。
- 工具链环境差异：`npm` 在当前宿主环境可能被外部 wrapper/ESLint hook 拦截，直接调用 `node scripts/lint-skills.js` 才执行仓库实际脚本。

## 3. PROVEN SOLUTION (验证有效的解决方案)
- 在 `dmml_linter.py` 中实现缩进感知的零依赖 `fallback_parse_yaml()`，并采用从 `initial_state` 出发的 BFS 检查可达性、DFS 检查跨上下文依赖环、`*_id` 后缀检查跨聚合引用，以及核对 `.ddd/02-events.yaml` 中的 `INVALIDATED` 状态。
- 在 `compile_events.py` 中统一使用 `json.dumps(text, ensure_ascii=False)` 输出合法 YAML 标量，分别校验事件块与 `READ-*` 读模型块的实质字段，并在解析为 0 条事件时以 `exit 1` 硬阻断。
- 在 `probes/tpipeose-interrogation.md` 显式固化 `## [FACT-001]` / `## [READ-001]` Markdown 模板，对外采用 CIT 案例访谈法与四级认识论保护（含 Chesterton's Fence 合规门禁）。

## 4. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)
- FORBIDDEN (禁止做法)：在跨项目使用的确定性脚本中依赖未经检查的第三方包并静默降级为无结构字典；或在无 `initial_state` BFS 遍历的情况下声称“状态机闭环”。
- USE (正规做法)：内置零依赖子集解析器并对输入/输出边界（空解析、转义引号、孤立闭环、`INVALIDATED` 血缘）编写正反断言测试。
- FORBIDDEN (禁止做法)：用粗暴的“移除不崩溃即删改”逻辑对待合规、审计与多团队契约规则，或将内部提取 Schema 直接抛给人类受访者逐字段盘问。
- USE (正规做法)：采用四级认识论分层（含 `compliance_gate`）与“案例先行 + 选项收敛 + 暂存待定区”的认知友好访谈协议。

## 5. SCALING TO AGENTS.MD (全局规则提炼)
- 提炼原子规则：`RULE: Deterministic skill scripts must be zero-dependency safe and contract-tested (FORBIDDEN: Silent fallback parsers or untested Markdown-to-YAML regex -> USE: Built-in subset parser, JSON-escaped YAML emitters, and positive/negative fixture tests)`
