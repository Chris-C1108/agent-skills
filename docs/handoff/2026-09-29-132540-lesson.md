# Session Lesson & Anti-Patterns: PowerShell 字符重定向与多环境技能分发排坑

- Timestamp: 2026-09-29 13:25:40 (Asia/Shanghai)
- Focus Area: PowerShell 脚本语法兼容性 & Agent Skills 静态 Lint 约束

## 1. PROBLEMS ENCOUNTERED (遇到的核心问题与故障)
- **现象描述 1**：在 `my-agent-sync/scripts/ai-sync.ps1` 中执行时报错 `Missing file specification after redirection operator` 与 `Missing type name after '['`。
- **现象描述 2**：在编写 `apply_patch` 或模板替换时，多行字符串中未转义的反引号或引号导致 V8 isolate 解析异常。

## 2. ROOT CAUSE ANALYSIS (根本原因剖析)
- **原因 1**：PowerShell 双引号字符串中包含 `>>> [3/5]` 时，`>` 会被解析为重定向运算符；`"...[...[...]]"` 中未转义的方括号会被 PowerShell 解析器误判为类型约束转换语法 `[TypeName]`。
- **原因 2**：跨平台脚本在不同终端环境编码（UTF-8 with/without BOM, ANSI）时容易破坏单双引号匹配。

## 3. PROVEN SOLUTION (验证有效的解决方案)
- **修复 1**：在 PowerShell 中输出日志提示一律去除裸 `>` 符号或改用单引号括起字符串，如 `Write-Host '[3/5] ...'` 代替 `Write-Host '>>> [3/5] ...'`。
- **修复 2**：PowerShell 的正则匹配字符串强制使用单引号，如 `'codex\s*=\s*\[([^\]]+)\]'`，彻底避免语法分析器误认。
- **修复 3**：文件修补与落盘优先采用 `[...].join('\n')` 结构化数组构造 patch，彻底免疫多行字符串转义陷阱。
- **Done right**：`Write-Host '[step] ...'` 与 `$pattern = 'codex\s*=\s*\[([^\]]+)\]'`

## 4. PITFALLS & ANTI-PATTERNS (避坑指南与反模式禁令)
- **FORBIDDEN (反模式)**：严禁在 PowerShell 双引号字符串内直接书写正则括号 `"[^"]"` 或日志重定向符 `">>>"`。
- **USE (正规做法)**：所有正则匹配必须使用单引号字面量；日志输出采用标准方括号 `Write-Host '[step] ...'`。
- **FORBIDDEN (反模式)**：严禁将单会话临时上下文或会话废话写入项目根目录 `AGENTS.md`（超过 150 行）。
- **USE (正规做法)**：超出 150 行的细则必须渐进式分流到 `docs/rules/*.md` 或通过 `docs/handoff/*-lesson.md` 沉淀。
- **Seen**：Seen 1× (2026-09-29)
